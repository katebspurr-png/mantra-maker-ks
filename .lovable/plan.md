

## Problem

The PWA service worker (generated by `vite-plugin-pwa`) aggressively caches all JS, CSS, and HTML assets. In the development/preview environment, this causes the old UI to persist even after code changes because the service worker serves from its cache instead of fetching fresh files.

## Root Cause

`registerType: "autoUpdate"` silently updates the service worker in the background, but it does **not** force a page reload. The old cached assets continue to be served until the new service worker activates and the user navigates again. In the Lovable preview environment, this creates a particularly sticky problem because builds restart frequently.

## Solution

Add `skipWaiting: true` and a `clientsClaim: true` directive to the workbox config so that new service workers take control immediately. Also add an explicit `self.skipWaiting()` to ensure the new worker doesn't wait for old tabs to close.

### Changes to `vite.config.ts`

In the `VitePWA` config, add to the `workbox` section:

```typescript
workbox: {
  skipWaiting: true,
  clientsClaim: true,
  // ... existing globPatterns, navigateFallback, runtimeCaching
}
```

This ensures:
- **`skipWaiting: true`** — New service worker activates immediately instead of waiting for all tabs to close
- **`clientsClaim: true`** — New service worker takes control of all open pages right away

These two lines together mean that whenever a new build is deployed, the updated service worker will immediately replace the old one and start serving fresh assets, eliminating the stale UI problem.

### Technical detail

No other files need to change. The `registerType: "autoUpdate"` combined with `skipWaiting` and `clientsClaim` is the standard recommended configuration for apps that should always show the latest version without requiring user action.
